## 1. 빌드 & 실행

```powershell
.\gradlew.bat compileJava   # 컴파일
.\gradlew.bat runData       # 모델·en_us·레시피·태그 생성 → src/generated/resources
.\gradlew.bat runClient     # 개발용 클라이언트
.\gradlew.bat runServer     # 데디케이티드 서버 (run/eula.txt 필요, 이미 있음)
.\gradlew.bat build         # build/libs/symagic-<ver>.jar
python tools/gen_textures.py   # 텍스처 16x16 (지팡이 1 + 마법책 10)
python tools/gen_logo.py       # 로고 512x512 (CF + 모드 목록)
```

배포 절차는 [PUBLISHING.md](../PUBLISHING.md), CurseForge 폼에 넣을 내용은
[docs/curseforge/등록정보.md](curseforge/등록정보.md).

**Gradle 데몬이 꺼져 있다.** `runServer`/`runClient`는 계속 떠 있으니 로그를 읽고 따로 죽여야 한다.

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.Name -eq 'java.exe' -and $_.CommandLine -like '*Projects\symagic*' } | Stop-Process -Force
```

## 3. 코드 구조 — 표 하나가 모드 전체다

```
src/main/java/com/syang/symagic/
├── SyMagic.java                    @Mod — 컴포넌트 · 아이템 · 탭 등록 3줄이 전부
├── registry/
│   ├── ModItems.java               지팡이 1 + Spell을 돌며 마법책 10 등록
│   ├── ModDataComponents.java      symagic:staff_spells 하나
│   ├── ModCreativeTabs.java        탭 1개
│   └── ModEnchantments.java        인챈트 3종 키 + 레벨→계수(spellPower/cooldown/reach)
├── world/item/
│   ├── Spell.java                  ★ 재료·원소·쿨·마법이 한 줄씩. 쿨다운 그룹 id도 여기서
│   ├── StaffItem.java              use() = 시전 / 웅크리면 전환. 번들식 끼우기·빼기. 툴팁
│   ├── StaffSpells.java            컴포넌트 값: 끼운 마법 목록 + 고른 칸. 생성 시 정규화
│   ├── SpellbookItem.java          툴팁만 있다. 스스로는 아무것도 안 한다
│   ├── StaffEvents.java            AnvilUpdateEvent — 책이 든 지팡이를 제물로 못 쓰게
│   └── Element.java                툴팁 색/글리프 (플레이 규칙 없음)
├── world/spell/
│   ├── SpellEffects.java           마법 10종 구현 (0.1.0 그대로)
│   └── SpellCooldowns.java         마법별 쿨다운 그룹 + 조회용 probe 스택
├── client/StaffCooldownDecorator.java  고른 마법의 쿨다운 막 (NeoForge IItemDecorator)
└── datagen/                        ModDataGenerators + 모델·en_us·레시피·아이템태그
src/main/resources/
├── data/symagic/enchantment/{spell_power,alacrity,arcane_reach}.json
└── data/minecraft/tags/enchantment/non_treasure.json   ← 바닐라 획득 경로에 올리는 한 줄
```

### 마법 추가하는 법

1. `Spell`에 한 줄 (id · 표시명 · 재료 · 원소 · 쿨 · 메서드 참조)
2. `SpellEffects`에 `(ServerLevel, Player, ItemStack staff, float power) -> void` 메서드 하나
3. `ModEnglishLangProvider.DESCRIPTIONS`에 영문 설명 한 줄 + `ko_kr.json`에 책 이름 · 마법 이름 · 설명
4. `tools/gen_textures.py`의 `SPELLS`에 (표지 색, 원소) 하나 → 스크립트 재실행
5. `.\gradlew.bat runData`

레시피·모델·태그·advancement는 전부 자동 생성된다. **지팡이는 건드릴 게 없다.**

## 4. 핵심 설계 결정 (다음 세션 필독)

- **지팡이는 하나, 칸은 3.** 단일 티어(활·철퇴처럼). 칸 제한이 없으면 한 자루가 전부 해서 고를 일이
  사라진다. 같은 마법은 한 자루에 한 번만 — `StaffSpells`가 생성 시 중복을 걸러 내고 3개로 자른다.
- **쿨다운을 스택에 달지 않는다.** 이게 0.2.0에서 제일 중요한 결정이다. 바닐라 `use_cooldown` 컴포넌트로
  고른 마법의 그룹을 달면 두 가지가 깨진다:
  1. `ServerPlayerGameMode#useItem`(과 클라이언트 `MultiPlayerGameMode`)이 **쿨다운 중인 스택의 사용 요청을
     `use()` 호출 전에 버린다.** 고른 마법이 쿨다운인 동안 웅크리고 우클릭 전환까지 막힌다.
  2. 사용 성공 직후 `ItemStack#applyAfterUseComponentSideEffects`가 그 컴포넌트의 **고정 초로 쿨다운을
     덮어쓴다.** 신속 시전이 날아간다.

  그래서 지팡이 자체 그룹(`symagic:staff`)은 절대 쿨다운에 안 걸고, 마법마다 `symagic:spell/<id>`로 건다.
  `ItemCooldowns`는 그룹을 직접 묻는 공개 메서드가 없어서, 마법마다 그 그룹을 단 **probe 스택**을 하나씩
  만들어 두고 그걸로 묻는다(`SpellCooldowns`). 쿨다운 그룹은 바닐라가 클라이언트로 동기화한다.
- **핫바 쿨다운 막은 직접 그린다.** 바닐라는 스택 자신의 그룹 쿨다운만 그리는데, 지팡이는 그룹이 비어 있다.
  `StaffCooldownDecorator`가 고른 마법의 그룹을 읽어 바닐라 `GuiGraphicsExtractor#itemCooldown`과 같은
  사각형 · 같은 색(`Integer.MAX_VALUE`)으로 그린다. 26.2에서 `GuiGraphics`는 `GuiGraphicsExtractor`로 이름이 바뀌었다.
- **끼우기/빼기는 26.2 번들 클릭을 그대로 따른다.** `overrideOtherStackedOnMe`(커서에 책, 지팡이 칸을 클릭)와
  `overrideStackedOnOther`(커서에 지팡이, 책 칸을 클릭) 둘 다. 왼쪽 = 넣기, 빈 손 오른쪽 = 고른 책 빼기.
  빈 지팡이에서는 `false`를 돌려 평소처럼 집히게 한다. 소리도 번들 것을 쓴다.
- **지팡이는 책을 저장하지 않고 마법을 저장한다.** 마법책은 상태가 없으니(내구 · 인챈트 없음) 빼면 새 책을 만든다.
- **책이 말없이 사라지는 길을 막았다.** 바닐라가 손상된 도구 두 개를 합치는 길은 셋이다.
  작업대 수리(`RepairItemRecipe`)는 `new ItemStack(item)`으로 결과를 **새로 만들어** 두 자루의 책이 다 날아가고,
  숫돌은 첫 입력만 복사해 두 번째 자루의 책이 날아간다 — 둘 다 `setNoCombineRepair()`로 끈다.
  모루는 이 설정을 보지 않으므로 `StaffEvents`가 `AnvilUpdateEvent`에서 **오른쪽(제물) 지팡이에 책이 있으면
  취소**한다(취소 = 결과 비움 · 비용 0, 양쪽에서 발생).
- **전환은 서버에서만 스택을 바꾼다.** 클라이언트 예측이 같이 바꾸면 슬롯 동기화와 겹쳐 두 번 넘어갈 수 있다.
  전환은 `CONSUME`(팔 안 휘두름), 시전은 `SUCCESS`.
- **왜 금괴인가.** 금은 바닐라에서 인챈트성이 가장 높다(22). 지팡이는 인챈트하는 물건이다. 어느 마법책
  재료와도 안 겹쳐서 로스터를 건드리지 않아도 됐다.
- **인챈트는 만들 수 없다.** `#minecraft:non_treasure`에 올려 두면 바닐라가 알아서
  `in_enchanting_table` · `tradeable` · `on_random_loot`에 접어 넣는다. 우리가 제공하는 획득 경로는 0개다.
  **마법책은 인챈트북이 아니다** — 반짝이지도 않고, 인챈트 태그에도 없다.
- **지팡이는 무기 태그에 넣지 않는다.** `#minecraft:enchantable/durability`와 `/vanishing`,
  그리고 `#symagic:enchantable/staff`뿐. 무기·채굴 태그에 넣으면 날카로움이 붙어 버린다.
- **인챈트성 0이면 마법부여대에 안 뜬다.** `Item.Properties#enchantable(n)`을 반드시 준다(지팡이 22).
- **화살 데미지 함정**: 바닐라 `AbstractArrow`는 데미지를 `ceil(비행속도 × baseDamage)`로 계산한다.
  서리 화살은 `baseDamage = 5×power / velocity`로 속도를 나눠 상쇄한다 —
  안 그러면 마력 확산이 사거리뿐 아니라 **데미지까지** 배로 키운다. (전작에서 실제로 겪은 버그다.)
- **점멸 착지**: 시야 광선이 맞은 지점에서 `0.6` 블록 되돌아온 자리에 내린다. 안 그러면 블록 안에 낀다.
  `resetFallDistance()`를 같이 불러 낙하 피해를 지운다.
- **돌풍의 `hurtMarked = true`**: 안 붙이면 서버가 속도 변화를 클라이언트에 안 보낸다.
- **다른 모드 이름을 문서에 쓰지 않는다.** README · CurseForge 카피 · CHANGELOG · 코드 주석 어디에도
  형제 모드를 언급하지 않는다. 한 번 데였다 — 갈라져 나온 원본 모드가 이름도 컨셉도 바뀌면서
  이 저장소의 소개문과 링크와 경로가 한꺼번에 낡았다. 이 모드가 하는 말은 "어떤 모드에도 의존하지
  않는다" 하나면 충분하고, 그 문장은 남의 정체성에 기대지 않는다. 설계 근거로 옛 설계를 인용할 때는
  **"전작"**이라고만 쓴다.

## 5. 이 환경의 함정

- **줄 끝을 섞지 말 것.** 저장소는 LF로 보관하지만 `core.autocrlf` 때문에 새로 체크아웃하면 작업본이
  CRLF가 된다. 편집 전에 `file <경로>`로 실제 상태를 보고 맞춘다 — 매칭은 `\R`로 하되 치환문에는
  `\R`을 쓸 수 없으니 그 파일이 실제로 쓰는 줄 끝을 직접 적는다.
- **PowerShell/Gradle 로그가 UTF-16일 수 있다.** grep 전에 `tr -d '\000'`.
  PowerShell로 띄운 Gradle 로그에는 stderr 경고가 `RemoteException` 줄로 감싸여 들어간다 —
  `Exception`으로 기동 실패를 기다리면 그 줄에 먼저 걸린다. `Done (`와 `Crash report`로 기다린다.
- **`python`은 된다.** 3.13.14 + Pillow 12.3 설치돼 있다(Store 배포판이지만 스텁이 아니라 실물이다).
  이미지 생성은 전부 python/Pillow다 — `tools/gen_textures.py`, `tools/gen_logo.py`.
- **Bash 히어독이 가끔 긴 Java 파일에서 따옴표 짝을 못 찾고 죽는다.** 그럴 땐 Write 도구로 쓴다.
- **26.2 API 참조**: `build/moddev/artifacts/minecraft-patched-26.2.0.88-sources.jar`를 풀어서 grep.
  바닐라 데이터(태그 JSON 등)는 `minecraft-patched-26.2.0.88.jar` 안에 있다.
  NeoForge 자체 소스는 `~/.gradle/caches/modules-2/files-2.1/net.neoforged/neoforge/26.2.0.88/*/neoforge-26.2.0.88-sources.jar`.
- **26.2 이름 바뀐 것**: `ResourceLocation` → `Identifier`, `GuiGraphics` → `GuiGraphicsExtractor`,
  `Player#displayClientMessage` → `sendOverlayMessage`(액션바).
